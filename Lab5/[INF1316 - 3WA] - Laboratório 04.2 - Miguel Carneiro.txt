QUESTÃO 1) Faça um programa para criar dois processos que se comunicam via pipe. O Pai lê do pipe enquanto o filho escreve no pipe. Exiba o resultado do que foi escrito e lido.
-----------------------------------------------------
EX1.C
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>

int main(void)
{

    int pid;
    int fd[2];

    pipe(fd);
    pid = fork();

    if(pid < 0)
    {
        perror("fork falhou");
        exit(1);
    }
    else if(pid == 0)
    {
        close(fd[0]);
        dup2(fd[1], 1);
        write(1, "Ola pai via pipe\n",17);

    }
    else
    {
        close(fd[1]);
        dup2(fd[0], 0);
        char buffer[20];
        int n = read(0, buffer, 20);
                wait(NULL);
        buffer[n] = '\0';
        printf("Recebi do meu filho: %s", buffer);
    }


    return 0;
}
-----------------------------------------------------
COMPILAÇÃO E EXECUÇÃO
$ gcc -o ex1 ex1.c
$ ./ex1
-----------------------------------------------------
RESULTADO
Recebi do meu filho: Ola pai via pipe
-----------------------------------------------------
CONCLUSÃO
O programa cria um pipe antes do fork(), de modo que pai e filho compartilham os mesmos descritores fd[0] (leitura) e fd[1] (escrita). O filho fecha a ponta de leitura (fd[0]), que não utiliza, e usa dup2() para redirecionar sua saída padrão (descritor 1) para a ponta de escrita do pipe, escrevendo a mensagem "Ola pai via pipe" através do write(1, ...). O pai faz o caminho inverso: fecha a ponta de escrita (fd[1]) e redireciona sua entrada padrão (descritor 0) para a ponta de leitura do pipe, bloqueando em read() até que o filho escreva algo. O wait(NULL) garante que o pai só imprima o resultado depois que o filho tiver terminado. O resultado confirma o funcionamento do pipe como canal FIFO de comunicação entre processos parentes: o dado escrito pelo filho em fd[1] foi corretamente lido pelo pai em fd[0].

QUESTÃO 2) Faça um programa para redirecionar a entrada e a saída, lendo os dados de um arquivo e gerando a saída em outro.
-----------------------------------------------------
EX2.C
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <signal.h>
#include <sys/wait.h>
#include <fcntl.h>

int main(void)
{

    int filein = open("entrada.txt", O_RDONLY);
    int fileout = open("saida.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    dup2(filein, 0);
    dup2(fileout, 1);
    char buf[128];
    int n;
    while ((n = read(0, buf, sizeof(buf))) > 0)
        write(1, buf, n);
    close(filein);
    close(fileout);

    return 0;
}

-----------------------------------------------------
CONCLUSÃO
O programa abre o arquivo entrada.txt para leitura e o arquivo saida.txt para escrita (criando-o caso não exista e truncando-o caso já exista), obtendo dois descritores de arquivo comuns. Em seguida, usa dup2() para substituir a entrada padrão (fd 0) pelo descritor do arquivo de entrada e a saída padrão (fd 1) pelo descritor do arquivo de saída. A partir daí, qualquer read(0, ...) passa a ler do arquivo entrada.txt e qualquer write(1, ...) passa a escrever no arquivo saida.txt, exatamente como ocorreria com o teclado e o monitor, sem que o restante do código precise ter conhecimento disso. Ao final da execução, o conteúdo de saida.txt é idêntico ao de entrada.txt, confirmando que o redirecionamento de entrada e saída via dup2() funciona de forma transparente para o processo.

QUESTÃO 3) Faça um programa para criar um pipe e executar dois processos que são utilitários do Unix que se comuniquem através do pipe criado, assim como a shell faz. Exemplo:
endler$ ps | wc
 28 28 310
-----------------------------------------------------
EX3.C
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    int fd[2];
    int pid1, pid2;
    pipe(fd);

    pid1 = fork();
    if (pid1 < 0)
    {
        perror("fork falhou");
        exit(1);
    }
    else if (pid1 == 0)
    {
        close(fd[0]);
        dup2(fd[1], 1);
        close(fd[1]);

        execlp("ls", "ls", "-l", NULL);
        perror("erro no execlp");
        exit(1);
    }

    pid2 = fork();
    if (pid2 < 0)
    {
        perror("fork falhou");
        exit(1);
    }
    else if (pid2 == 0)
    {
        close(fd[1]);
        dup2(fd[0], 0);
        close(fd[0]);

        execlp("wc", "wc", "-l", NULL);
        perror("erro no execlp");
        exit(1);
    }

    close(fd[0]);
    close(fd[1]);

    waitpid(pid1, NULL, 0);
    waitpid(pid2, NULL, 0);

    return 0;
}

-----------------------------------------------------
CONCLUSÃO
O programa reproduz o comportamento da shell ao interpretar um comando com pipe, como "ls -l | wc -l". Um único pipe é criado antes dos dois fork()'s. No primeiro processo filho, a saída padrão (fd 1) é redirecionada para a ponta de escrita do pipe através de dup2(), e em seguida o processo se transforma no utilitário ls -l via execlp(), de modo que toda a listagem de arquivos passa a ser escrita no pipe em vez do terminal. No segundo processo filho, a entrada padrão (fd 0) é redirecionada para a ponta de leitura do pipe, e o processo se transforma no utilitário wc -l, que passa a contar as linhas recebidas pelo pipe em vez de ler do teclado. O processo pai fecha as duas pontas do pipe, pois não as utiliza, e aguarda o término dos dois filhos com waitpid(). O resultado (11) corresponde à quantidade de linhas produzidas pelo ls -l no diretório do laboratório, demonstrando que a comunicação entre os dois utilitários através do pipe funcionou da mesma forma que o operador "|" da shell.

QUESTÃO 4) Faça um programa que cria dois processos leitores e um processo escritor em uma mesma pipe. Faça o escritor dormir metade do tempo dos leitores, e mostre como os leitores consomem os dados produzidos pelo escritor. Obs: não force uma alternância controlada por SIGSTOP/SIGCONT.
-----------------------------------------------------
EX4.C
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <string.h>
#include <sys/wait.h>

#define NUM_MENSAGENS 10
#define TEMPO_LEITOR 2
#define TEMPO_ESCRITOR (TEMPO_LEITOR / 2)

void escritor(int fd_escrita)
{
    char msg[64];

    for (int i = 1; i <= NUM_MENSAGENS; i++)
    {
        snprintf(msg, sizeof(msg), "mensagem %d do escritor\n", i);
        write(fd_escrita, msg, strlen(msg));
        printf("[escritor] produziu: %s", msg);
        fflush(stdout);
        sleep(TEMPO_ESCRITOR);
    }

    close(fd_escrita);
}

void leitor(int fd_leitura, int id)
{
    char buf[64];
    ssize_t n;

    while ((n = read(fd_leitura, buf, sizeof(buf) - 1)) > 0)
    {
        buf[n] = '\0';
        printf("[leitor %d] consumiu: %s", id, buf);
        fflush(stdout);
        sleep(TEMPO_LEITOR);
    }

    close(fd_leitura);
}

int main(void)
{
    int fd[2];
    pid_t pid_escritor, pid_leitor1, pid_leitor2;

    if (pipe(fd) < 0)
    {
        perror("pipe falhou");
        exit(1);
    }

    pid_escritor = fork();
    if (pid_escritor < 0)
    {
        perror("fork falhou");
        exit(1);
    }
    else if (pid_escritor == 0)
    {
        close(fd[0]);
        escritor(fd[1]);
        exit(0);
    }

    pid_leitor1 = fork();
    if (pid_leitor1 < 0)
    {
        perror("fork falhou");
        exit(1);
    }
    else if (pid_leitor1 == 0)
    {
        close(fd[1]);
        leitor(fd[0], 1);
        exit(0);
    }

    pid_leitor2 = fork();
    if (pid_leitor2 < 0)
    {
        perror("fork falhou");
        exit(1);
    }
    else if (pid_leitor2 == 0)
    {
        close(fd[1]);
        leitor(fd[0], 2);
        exit(0);
    }

    close(fd[0]);
    close(fd[1]);

    waitpid(pid_escritor, NULL, 0);
    waitpid(pid_leitor1, NULL, 0);
    waitpid(pid_leitor2, NULL, 0);

    return 0;
}

CONCLUSÃO
Um único pipe é compartilhado por três processos filhos: um escritor e dois leitores, todos criados a partir do mesmo processo pai antes de qualquer fechamento de descritores, garantindo que todos herdem as duas pontas do pipe. O escritor fecha a ponta de leitura e produz 10 mensagens, dormindo metade do tempo (1 segundo) do que cada leitor dorme (2 segundos) entre uma operação e outra. Os dois leitores fecham a ponta de escrita e ficam bloqueados em read() disputando os dados disponíveis na mesma pipe: como o pipe não direciona dados para um leitor específico, cada mensagem escrita é consumida por apenas um dos dois leitores, de forma alternada e não determinística, dependendo de qual processo estava com a chamada read() pendente no momento em que o dado chegou. Como o escritor produz mais rápido do que cada leitor individualmente consome, o pipe atua como um buffer que se enche e distribui as mensagens entre os dois leitores conforme eles ficam disponíveis, sem qualquer sincronização forçada por sinais (SIGSTOP/SIGCONT): a alternância observada no resultado é consequência natural da concorrência entre os dois leitores pelo mesmo recurso compartilhado.
